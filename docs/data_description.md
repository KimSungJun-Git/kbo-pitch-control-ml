## 2. 타깃 변수(`control_success`)의 실체 및 구조 분석

대회 공식 규칙상 투구의 결과는 **1(제구 성공)** 또는 **0(제구 실패)**의 이진 타깃으로 주어지며, 모델은 0~1 사이의 **연속 확률값**을 제출해야 합니다.

### (1) 주최측 제구 성공/실패 판정 메커니즘 (역산 규명)
데이터 분석 및 보조 라벨 역산 결과, 제구 판정은 다음 3가지 조건의 결합으로 이루어집니다:

```text
                  [ 투구 결과 코스 / 판정 ]
                             │
     ┌───────────────────────┼───────────────────────┐
     ▼                       ▼                       ▼
【가운데/위험 코스】       【포수 요구 반대성】        【그 외 일반 투구 (Clean)】
(middle_rate = 1)       (reverse_rate = 1)          (전체의 약 65.5%)
     │                       │                       │
     ▼                       ▼                       ▼
 [ 항상 제구 실패 ]       [ 항상 제구 실패 ]        [ 대다수 제구 성공 ]
 (control_success = 0)   (control_success = 0)     (스트라이크존 외곽 형성)
                                                   * 볼 판정 시에만 0.591로 하락
```

1. **가운데 또는 위험 코스(`middle = 1`)**: 포수가 요구한 코스와 무관하게 타자가 타격하기 쉬운 존 한가운데로 몰린 공 → **무조건 제구 실패(0)**
2. **의도 반대성 투구(`reverse = 1`)**: 포수의 미트 위치(바깥쪽/몸쪽)와 정반대로 날아간 실투 → **무조건 제구 실패(0)**
3. **정상 유효 투구(`clean`)**: 위 두 실투를 피한 경우 대부분 제구 성공(1)으로 인정됨.

### (2) 극저신호(Low-signal) 및 기저율(Base Rate) 시계열 드리프트
* **평균 성공률**: 전체 6개년 평균 제구 성공률은 약 **0.5238**로 거의 동전 던지기에 가까운 극저신호 데이터입니다 (투구 직전 정보만으로 결과와의 상관계수는 약 **0.104** 수준).
* **연도별 기저율 하락 추세 (Concept Drift)**:
  - 2019년: **0.5647**
  - 2020년: **0.5312**
  - 2021년: **0.5189**
  - 2022년: **0.5094**
  - 2023년: **0.4982**
  - 2024년: **0.4861**
  - **2025년 (평가 데이터 실측 복원)**: **0.4609**
* **시사점**: 학습 데이터로 학습한 트리 모델은 과거의 높은 성공률 기준선(0.52)을 학습하므로, 2025 시즌 평가 시 예측 확률값이 전반적으로 과대 추정됩니다. 따라서 **기저율 오프셋 보정 및 사후 캘리브레이션($\alpha^*, \beta^*$)**이 필수적인 성능 레버로 작용합니다.

## 4. 데이터 감사(Audit)를 통해 발견한 5대 핵심 결함과 해결책

프로젝트 초기 베이스라인(941점)에서 최고점(1137점)으로 도약할 수 있었던 원동력은 라이브러리 튜닝이 아닌 **데이터 전수 감사**에 있었습니다.

### ① `asof_pitcher_n` 커리어 통산 누수/왜곡 분해 (+51.91점, t41)
* **결함**: 변수명만 보면 당해 시즌 누적으로 보이지만, 실제 데이터 감사 결과 2019년부터 누적된 **통산 커리어 투구수**였습니다. 이로 인해 10년 차 베테랑 투수는 당해 시즌 폼이 완전히 망가져도 커리어 누적으로 인해 신호가 심각하게 왜곡되었습니다.
* **해결**: `count = round(rate * n)` 공식을 역산하여 통산 성공 횟수를 복원한 뒤, **당해 시즌 시작 전 스냅샷 값을 차감하여 "순수 당해 시즌 내 성분"을 독립된 8개 피처로 분리**.

### ② 학습 시 Groupby vs 추론 시 스냅샷 불일치(Skew) 해결 (+20.66점, t45)
* **결함**: `train.csv`를 학습할 때는 Pandas `groupby().expanding()`으로 과거 누적을 실시간 계산했으나, `script.py` 추론 환경에서는 미리 피클로 덤프한 `snap.pkl` 딕셔너리를 조회하면서 **특정 8개 피처의 계산 시점과 분모가 어긋나는 추론 스큐(Serving Skew)**가 존재했습니다.
* **해결**: 피처 생성 로직을 단일화하고 스냅샷 정합성 검증 테스트를 파이프라인에 추가하여 왜곡 제거.

### ③ Cold-Start 결측치 대치: Median 대신 고정 센티넬(-999) 채택 (+7.34점, t59)
* **결함**: 신인 투수나 시즌 첫 등판 선수는 `asof_pitcher_*` 값들이 NaN(결측)입니다. 베이스라인의 컬럼별 `Median` 대치는 "이력 없음(알 수 없음)"을 "리그 평균 선수"로 둔갑시켜 트리 모델에 가짜 확신을 주었습니다.
* **해결**: `-999` 고정 센티넬 값을 할당하여 트리가 "이력 미보유 표본"을 독립된 분기 가지로 명확히 분리 학습할 수 있도록 개선.

### ④ 소표본 선수의 베이지안 수축 (Shrinkage $K$) 최적화 (+9.10점, t164 챔피언)
* **결함**: 투구수 5개인 투수가 제구 5개를 다 성공했다고 성공률 1.0(100%)을 그대로 사용하면 치명적인 과적합이 발생합니다.
* **해결**: 선수별 관측 성공률($\bar{y}$)과 리그 전체 평균($\mu$)을 표본수($n$)에 따라 가중 결합하는 베이지안 수축 공식 적용:
  $$\hat{p} = \frac{n \cdot \bar{y} + K \cdot \mu}{n + K}$$
* 특히 기존의 단일 상수($K=25.0$) 대신, **투수($K_p=25$), 타자($K_b=15$), 팀($K_t=50$) 등 정보 밀도별 최적 $K$ 딕셔너리**를 구축하여 최종 챔피언 점수 달성.

### ⑤ 대회 규칙 4(평가 데이터 행 독립성) 준수 설계
* **규정**: `test.csv`의 다른 행을 참조하거나 전체 24.5만 건의 평균/분포를 집계해 사후 보정하는 행위는 엄격히 실격 처리됩니다.
* **구현**: 모든 피처 엔지니어링은 단 1개의 행이 단독으로 주어져도 동일한 출력을 내는 **완전 독립 벡터화 함수**로 구현되었습니다 (`preflight.py` 전수 검증 통과, 오차 $0.000\text{e+}00$).

## 5. 보조 데이터셋 명세 (`trackman_history.csv`)

2019~2024년 정규리그 및 퓨처스리그 투구의 3D 레이더 추적 로그 1,793,078행입니다 (2025년 데이터는 비공개).

| 컬럼명 | 단위/타입 | 물리적 의미 및 특성 |
|---|---|---|
| `rel_speed` | mph | 투수 손에서 공이 떠나는 순간의 초속 (구속) |
| `spin_rate` | rpm | 투구의 분당 회전수 |
| `induced_vert_break` | inches | 공기역학적 마그누스 힘에 의해 발생하는 유도 수직 무브먼트 |
| `horz_break` | inches | 좌우 횡 무브먼트 |
| `extension` | feet | 투수가 투구판에서 홈플레이트 쪽으로 끌고 나와 릴리스한 거리 |
| `rel_height` / `rel_side` | feet | 공이 릴리스된 3차원 공간 좌표 |
| `zone_speed` | mph | 홈플레이트 통과 시점의 종속 (초속 대비 감속률 측정 가능) |
| `tagged_pitch_type` | String | 포심, 슬라이더, 커브, 체인지업 등 수동 태깅 구종 |
| `pitch_type_group` | Categorical | `fastball`, `breaking`, `offspeed`, `other` 대분류 |

* **실험 결론 및 활용 전략**:
  - 트랙맨 ID(`pitcher_trackman_id`)와 메인 투수 ID(`pitcher_id`) 간 1:1 매핑 테이블이 제공되지 않아 헝가리안 알고리즘으로 623명을 매칭했으나, 트랙맨 피처 단독 결합은 오히려 점수가 하락했습니다 (`-1.9%`).
  - 트리가 이미 `pitcher_id`를 통해 투수의 신원을 외우고 있어 정적 물리치는 중복 신호였기 때문입니다.
  - 최종 챔피언 모델에서는 트랙맨 피처를 메인 테이블에 억지로 붙이지 않고, **트랙맨 전용 모델(`tm_full`)과 기본 모델(`no_asof`)을 각각 독립 학습한 후 앙상블 블렌딩(0.485 : 0.485)**하는 방식으로 신호 다양성을 극대화하여 회수했습니다.
