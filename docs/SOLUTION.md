## 1. 문제의 성격 — 극저신호

가장 먼저 파악해야 했던 건 **이 문제에 신호가 거의 없다**는 사실이다.

```
train.csv   1,475,092행 × 49컬럼   (2019~2024)
test        245,789행              (2025, 비공개)
제구 성공률  0.5238 → 동전 던지기에 가까움
```

베이스라인 RF의 BSS가 0.0042, 우리 최종 모델도 0.0079다. **47개 피처가 결과 분산의
1% 미만을 설명한다.** 이 사실이 전략 전체를 결정했다.

- 모델 용량을 키우거나 튜닝하는 방향은 무의미하다 (실제로 전부 실패, 7절)
- 개선은 **모델이 구조적으로 표현할 수 없는 것**을 넣어줄 때만 나온다
- 개선 폭이 소수점 셋째 자리에서 움직이므로, **정직한 측정 도구가 먼저** 필요하다

## 3. 핵심 설계 ① — 정직한 시간축 3분할

### 문제

베이스라인 노트북은 2024를 검증셋으로 쓰면서 early stopping도 2024로 건다.
**반복수를 정답 보고 고른 뒤 그 정답으로 채점하는 구조**라 점수가 부풀려진다.

### 해법

실제 과제는 **≤2024 학습 → 2025 예측**, 즉 1년 앞을 맞히는 문제다. 검증도 같은 모양이어야 한다.

```
반복수 결정 :  ≤2021 학습,  2022 로 early stopping     (1년 간격)
정직한 평가 :  ≤2023 재학습 → 2024 홀드아웃            (1년 간격) ← 이 점수만 믿는다
제출용      :  ≤2024 재학습 → model/lgbm.pkl
```

세 구간이 시즌 단위로 완전히 분리된다. 학습·반복수 결정·채점에 쓰인 시즌이 겹치지 않는다.

### 간격을 반드시 1년으로 맞춰야 하는 이유

간격을 2년으로 벌린 구조(≤2022 학습 → 2024 평가)도 시험해봤는데 **BSS가 음수로 붕괴**했다.

```
2년 간격  BSS -0.007560   best_iteration = 15
1년 간격  BSS +0.005993   best_iteration = 181
```

원인은 early stopping 오염이다. 학습셋 기저율(0.5395)과 검증셋 기저율(0.4999)이 어긋나 있으면,
부스팅을 시작하자마자 검증 logloss가 나빠진다. **"과적합이다"가 아니라 "기저율이 다르다"를 보고
15회에서 멈춰버려** 모델이 실제 신호를 배우기도 전에 중단된다.

즉 시즌 drift는 예측값만 망가뜨리는 게 아니라 **학습 제어 자체를 오염시킨다.**

### 2023을 검증 연도로 쓰면 안 되는 이유

2022→2023에 `game_type=F`(퓨처스, 전체의 10.9%)의 제구 성공률이 **0.709 → 0.473으로 반전**했다.

```
전체 기저율 낙폭 -0.029 의 분해
  F 그룹  -0.236 × 비중 0.109  =  -0.0257
  R 그룹  -0.0006 × 비중 0.891 =  -0.0005
```

낙폭의 거의 전부가 F 한 그룹에서 나온다. 레짐 전환 해라 이 해로 고른 하이퍼파라미터 순위는
2024로 전이되지 않았다 (2023 1위 설정이 2024에서 꼴찌).

## 4. 핵심 설계 ② — 시즌 기저율 오프셋 (+13.8%)

### 문제

제구 성공률이 매년 단조 하락한다.

```
2019  0.5647
2020  0.5327
2021  0.5328
2022  0.5289
2023  0.5000
2024  0.4861     최근 3시즌 기울기 -0.0214/년
```

학습 시즌의 기저율을 그대로 들고 나가면 예측이 체계적으로 높게 나온다. Brier는 이 편향에
제곱으로 벌점을 매기므로 손실이 크다. 실제로 베이스라인 RF는 2024 홀드아웃에서
편향 +0.0151을 내고, 그것만으로 BSS 0.0009(환산 91점)를 잃는다.

### 해법 — 기저율을 모델 밖으로 분리

시즌 기저율의 logit을 `init_score`로 빼고 학습시킨다. 모델은 **"그 시즌 평균 대비 편차"**만
학습하게 된다. 추론 시에는 과거 추세로 외삽한 목표 연도 기저율을 상수로 더한다.

```
학습:  init_score_i = logit( r_{season(i)} )              r 은 train.csv 실측
추론:  p = sigmoid( raw_score + logit(r̂_target) )         r̂ 은 선형 외삽

r̂_2025 = 0.4747  →  offset = logit(0.4747) = -0.1013
```

### 결과

```
오프셋 없음   BSS 0.005993   예측평균 0.4974 / 실제 0.4861   편향 +0.0113
오프셋 적용   BSS 0.006822   예측평균 0.4865 / 실제 0.4861   편향 +0.0004
                  +13.8%
```

외삽값(0.4918)이 실제(0.4861)보다 높았는데도 최종 편향이 +0.0004로 붙었다.
`season`이 피처로 남아 있어 모델 raw score가 나머지를 흡수했기 때문이다.

### 규정 준수

`offset`은 **학습 시점에 확정되는 스칼라 하나**이고 `train.csv`의 시즌별 성공률만으로 산출된다.
모든 행에 같은 값이 더해지므로 평가 데이터의 다른 행을 참조하지 않는다 (대회 규칙 4).

> 개발 초기에 `p - (p.mean() - r̂)` 형태를 시도했다가 폐기했다. `p.mean()`은 **test 전체
> 예측의 평균**이라 "평가 데이터 전체를 보고 만든 사후 보정값"에 해당하는 명백한 위반이다.
> 학습 시점에 상수를 확정하는 현재 방식으로 대체했고, 성능도 대부분 보존됐다.

### 검증한 대안들

| 방식 | BSS |
|---|---|
| **선형 외삽 (채택)** | **0.007794** |
| 직전 시즌값 그대로 | 0.007508 |
| `game_type`별 그룹 오프셋 (직전값) | 0.007270 |
| `game_type`별 그룹 오프셋 (선형 외삽) | 0.005504 |

`game_type=F`의 궤적이 예측 불가(2019~2022 요동 → 2023 급락)라 그룹별로 나누면 분산만 커진다.

## 5. 핵심 설계 ③ — 파생 피처 (+14.2%)

### 원칙: 트리가 못 만드는 것만 넣는다

트리는 **한 번에 한 컬럼만** 자른다. 두 컬럼의 차·비·엔트로피 같은 결합은 계단으로만
근사할 수 있다. 그래서 그런 형태만 골라 12개를 만들었다.

```python
count_stress     = balls_before − strikes_before
is_same_hand     = (pitcher_hand == batter_hand)
matchup_gap      = asof_pitcher_success_rate − asof_batter_success_rate
matchup_gap_mid  = asof_pitcher_middle_rate  − asof_batter_middle_rate
form_delta{1,3,5}= asof_pitcher_prev{k}_game_success_rate − asof_pitcher_success_rate
pitch_entropy    = −Σ rate·log(rate)          (fastball / breaking / offspeed)
clutch           = (inning≥7) × li × (num_runners_on+1)
is_full_count / is_scoring_position / quick_motion
```

전부 **한 행 안의 사칙연산**이라 행 독립 원칙을 지킨다.

### 결과 — 가설의 절반만 맞았다

```
파생 피처 12개가 전체 gain 의 8.6% 차지

★ is_same_hand          1.86%   전체 13위 / 58
★ pitch_entropy         1.49%   전체 18위
★ form_delta5           1.26%   전체 19위
★ form_delta3 / 1       0.88 / 0.82%
★ matchup_gap           0.67%
★ count_stress          0.65%
─────────────────────────────────
★ is_scoring_position   0.03%   전체 55위   ← 사실상 무의미
★ quick_motion          0.02%   전체 56위   ← 사실상 무의미
```

**두 컬럼을 결합한 것(`is_same_hand`, `matchup_gap`, `form_delta`)과 세 컬럼을 요약한 것
(`pitch_entropy`)만 값어치가 있었다.** 반면 `is_scoring_position`, `quick_motion`처럼
기존 컬럼의 단순 조건 조합은 트리가 이미 스스로 하고 있어 기여가 0에 수렴했다.

야구 도메인 지식으로 만든 "주자 상황 지표"류가 정확히 이 무의미한 쪽이었다.
**도메인 그럴듯함보다 모델의 표현 한계가 기준이었다.**

### 2차 파생은 실패

같은 원칙으로 7개(`ball_strike_gap`, `form_vol`, `exp_gap`, `abs_score_diff` 등)를 더 만들었으나
BSS가 0.007794 → 0.007612로 떨어졌다. 1차에서 뽑아낼 수 있는 건 이미 다 뽑았고,
같은 컬럼들로 차이를 더 만드는 건 노이즈만 추가한다.

## 6. 시드 앙상블 (+0.83%)

Brier는 예측 분산에 그대로 벌점을 준다. `random_state`만 42~46으로 바꾼 5개 모델의
**확률을 평균**낸다 (logit이 아니라 확률 단계에서 평균 — Brier가 확률 위에 정의되므로).

```
단일 시드    BSS 0.007794
5시드 평균   BSS 0.007859     +0.83%
```

`subsample=0.8, colsample_bytree=0.8`로 이미 무작위성이 들어가 있어 시드만 바꾼 다양성은
크지 않다. 추론 비용은 무시할 수준(5모델 × 181트리 = 2.5초)이라 유지했다.

## 9. 시도했으나 실패한 것

상세는 [CHECKLIST.md](CHECKLIST.md) 6절. 요약하면:

**모델 쪽을 만진 시도는 전부 0이었다.** 하이퍼파라미터 16조합(`num_leaves` 15~127,
`learning_rate` 0.03~0.08, `reg_lambda` 1~100)을 훑어도 최고와 최저 차이가 6%에 불과했다.
**용량 부족이 아니라 신호 부족**이라는 뜻이다.

**trackman은 매칭에 성공하고도 실패했다.** `(season, game_month, game_dayofweek)` 셀별
투구수를 행정규화 → 셀평균 제거 → 좌우별 헝가리안 배정으로 투수 623/792명을 매칭했고
메인 투구의 95.8%를 커버했다 (매칭에 쓰지 않은 총 투구수가 상관 0.959로 독립 검증됨).

그런데 BSS가 1.9% 떨어졌다. **`pitcher_id`가 이미 피처라 트리가 투수 신원을 직접 외우고 있어서**
투수당 정적인 물리 지표는 중복이었다. 게다가 `asof_pitcher_success_rate`는 제구 결과를 직접
측정한 값이고 구속·회전수·릴리스포인트는 그 상류 원인이라, 결과를 이미 가진 상태에선
덧붙일 정보가 없다.

## 11. 요약

이 문제에서 통한 것은 하나로 요약된다 — **모델이 구조적으로 표현할 수 없는 것을 찾아
밖에서 넣어주기.**

- 기저율의 시간 변화 → 트리는 학습에 없는 `season=2025`로 외삽할 수 없다 → **오프셋으로 분리**
- 두 컬럼의 차이·엔트로피 → 트리는 축 하나씩만 자른다 → **파생 피처로 명시**
- 예측 분산 → 단일 모델은 못 줄인다 → **시드 평균**

반대로 모델 안에서 해결하려는 시도(튜닝, 앙상블, 더 많은 피처)는 예외 없이 실패했다.
신호가 1% 미만인 문제에서는 짜낼 것이 남아 있지 않기 때문이다.
